> **EP** — provenance protection is defined by the registry, not by a directory. Any file
> named in any `decided_by` value in `dim_headline_number` is protected from the archive
> sweep wherever it sits. The sweep resolves that set by querying the registry and fails
> loudly if it would touch a member, rather than relying on a directory whitelist.

## 1 · Decisions needed

**None.** The instruction was explicit on the two things not to do — do not create
`docs/decisions/`, do not move the named documents — and I did neither.

**One thing to note for whoever writes the sweep.** There is **no archive-sweep script in
the repo**; the sweep is a manual process, referred to in CLAUDE.md as "the 29 July archive
sweep". So EP is implemented as **the guard that process must call**, with a CLI that makes
calling it a one-liner. If a sweep is ever scripted, `assert_sweep_safe()` is the function
it imports, and it should be the **first** thing that runs.

## 2 · Checks

| check | tests | result |
|---|---|---|
| **resolution** | every file named in a `decided_by` value exists somewhere in the repo | **PASS** — 143 rows, **14 files**, all resolve. `list` exits 1 if one ever goes missing |
| **guard, positive** | a sweep containing a protected file is refused | **REFUSED**, naming the file and the `number_id`s that protect it |
| **guard, negative** | a sweep of ordinary files is allowed | **ALLOWED** |
| **operational** | the CLI form a sweep would actually use | refuses `T8_gateA_pin_decisions.md` (exit 1), allows the unprotected candidate (exit 0) |

**The negative control is not decoration.** A positive fixture alone is passed by a guard
that refuses everything, which would be worse than no guard — it would stop the sweep
entirely and get switched off. The test asserts **catch, allow and resolve together**, or
it fails. That is I-42's discipline with 143 numbers behind it.

**What the fixture prints on the positive case** — the message is the deliverable as much
as the exit code, because a sweep operator needs to know *why*:

```
RULING EP - SWEEP REFUSED. These files are named in dim_headline_number.decided_by
and are the provenance chain for pinned numbers. They are protected wherever they sit.
  docs\reference_update\T8_gateA_pin_decisions.md
      protected by: bala29ca_floor_gap_periodwise, ... (+29 more)
```

## 3 · Overrides

**None.** The design seat's specification was complete and the two prohibitions were
explicit.

One design choice worth stating: where a `decided_by` value names a **bare basename**
rather than a path, **every copy in the repo is protected**, not just the canonical one.
Over-protecting is the safe direction for a guard whose failure mode is deleting the
provenance chain. It shows up in the set as `build_T8_gateB_dim_headline_number.py`
appearing twice — once live, once inside a review bundle.

**The hand-maintained list was wrong in both directions at once, and the measurement is
the argument for EP.**

CLAUDE.md rule 3 named `docs/decisions/` — **a directory that does not exist and has no git
history** — and two documents inside it. Resolved from the registry:

| | |
|---|---|
| files actually protected | **14** |
| of the two names in CLAUDE.md, protected | **1** (`T8_gateA_pin_decisions.md`, by 35 numbers) |
| of the two names in CLAUDE.md, protected by **zero** rows | **1** (`T8_T9_T10_gateA_decisions.md`) |

So the rule **named a file that nothing protects** and **omitted thirteen that 143 numbers
depend on**, while pointing at a directory that was never there. Every one of those is a
drift a registry-derived set cannot have.

**The 13 that were unlisted are not obscure.** They include `Gayini_T10_v2_spec.md` (24
numbers), `Gayini_pack_v1_3_task_list.md` (9), `Gayini_REG1_REG2_spec.md` (9),

`docs/reference_update/` and `docs/change_reports/`, **both of which the archive sweep
does touch**.
